# 设计摘要

Resonance Clock 的首版目标是一个独立的 Forge + Curios 遗物 Mod：装备遗物后提供投影式钟环和翼的外观、可选飞行，以及一次受服务端控制的状态回溯。

## 已实现范围

- Curios `charm` 槽位遗物
- I–XII 钟环和简化投影翼渲染层
- 默认关闭的飞行授权
- 时光扭结：记录状态、等待、校验安全位置后恢复允许状态
- 服务端配置、中文和英文文本

## 时光扭结边界

会处理位置、维度、生命、饥饿/饱和度、氧气、燃烧、伤害吸收和允许管理的原版效果。不会恢复背包、装备、经验、方块、容器、掉落物或第三方资源。目标不安全、维度无效或传送校验失败时会取消本次恢复而非部分恢复。

## 明确限制

飞行使用原版 `mayfly`，原版状态无法安全表达多来源所有权，因此它是管理员选择启用的独占模式，不应与其他飞行授权并用。

完整设计原稿和原始需求仅保留在本地资料中，不随此仓库分发。

## 0.2.0：时之紊乱与净化

时之紊乱使用独立于时光扭结的持久化根，只在首次施加时记录固定快照，并按可配置的在线服务端 tick 周期尝试恢复。死亡、离线及功能禁用期间不推进；死亡 clone 复制诅咒。恢复失败会跳过本轮并重启完整周期，避免逐 tick 重试。

解除入口仅包括自己的净化物品、管理员命令，以及通过启用、装备、冷却检查后成功创建的新时光扭结锚点。重复施加不覆盖快照，已有扭结时拒绝施加；同玩家状态变更以玩家持久数据为锁串行化。

快照和两个持久化根采用当前版本严格校验。未知版本或损坏数据不会被猜测迁移或恢复，而是冻结等待管理员清除。请求限流使用主世界服务端 `gameTime`，避免玩家实体重建导致实体 tick 回零后长时间拒绝请求；该修复已有纯逻辑探针证据，但尚无真实玩家重生端到端复测。

管理员调试命令仅在当前服务器会话中启用日志并读取已有状态，不修改锚点、冷却或诅咒。具体字段与隐私边界见 [运行时调试](debug.md)。
